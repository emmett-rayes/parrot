# CLAUDE.md — Parrot

Onboarding for AI coding agents (`AGENTS.md` points here). The reasons behind every rule below are in
`docs/DESIGN.md`, together with the rejected alternatives and what the library leaves out on purpose; the known
compiler issues, with reproductions, are in `docs/compiler-issues.md`. Check them before adding a construct or fighting
the compiler. Treat the design decisions as settled; reopen one only with a new argument, and record the result there.

## What Parrot is

A parser-combinator library derived from category theory, in Scala 3, with a tutorial (`docs/TUTORIAL.md`) that the
library should read as a consequence of. No runtime dependencies (ScalaTest and ScalaCheck in `Test` only); add none:
the point of the project is to build the structures from scratch.

- `parrot.category`: categorical structures (categories, functors, limits, promonads, monoidal structures, strength,
  restriction, traces, Conway and Elgot operators, recursion, monads and transformers), each with its laws as
  executable code.
- `parrot.parser`: `ParserAlgebra`, the PEG combinators as a bundle of those structures, and two interpreters:
  `ReferenceParser`, the executable specification built only from library structures (slow and not stack-safe, so
  JSON tests parse on a 1 GiB-stack thread, `JsonFixtures.onDeepStack`; never optimize it at the expense of clarity),
  and `StrictParser`, an optimizing interpreter over a normalized AST (`Node`) of reified pure functions (`Fn`).
- `parrot.json`: `JsonGrammar`, written once against any `ParserAlgebra`; the end-to-end test and benchmark workload.

## Build and test

Scala 3.10.0 (pinned in `build.sbt`, `pants.toml`, `BUILD` and `check-snippets.py`), sbt 2.0.12, Pants 2.33.1. Run
everything from the repository root (test fixtures resolve paths from it).

```sh
sbt --client Test/compile
sbt --client testFull                  # whole suite (~750 tests, under a minute); regenerates docs/law-status.md
sbt --client "testOnly parrot.parser.*"
sbt --client "Test/runMain parrot.json.JsonBenchmark nativejson-benchmark"     # [--reference] measures both
python3 docs/tutorial/check-snippets.py --classpath target/out/jvm/scala-3.10.0/parrot/classes   # after compiling
pants check <file>                     # fast single-file type-check; also: pants test <test-file>
```

- **`sbt test` is incremental in sbt 2 and may run nothing**: use `testFull`.
- sbt 2 caches by source hash: cached compiles don't replay warnings, and `clean; compile` can restore stale class files
  (`IncompatibleClassChangeError`) or replay a stale failure. Edit any source to force a fresh compile. Build tasks
  with side effects need `Def.uncached`.
- Pants parses with Scalameta through the in-repo plugin `scala_override` (see its own `CLAUDE.md`), which rejects some
  syntax scalac accepts: no applied constructor types (`Functor(J, C)` as a type), backtick `` `^` `` as a type
  operator, and avoid a pure function arrow inside a polymorphic function type (`[X] => A -> B`).
- `docs/law-status.md` is generated by every test run; never edit it. Don't edit the vendored corpora in
  `src/test/resources/json`.

**Before finishing a change:** `testFull` passes with no warnings. After touching `StrictParser`, `Scanner`, `CharSet`
or `Fn`, run the JSON benchmark (JSON_checker 34/34, ≈ 110 MiB/s). After changing the tutorial, or library code it
uses, run the snippet checker.

## Compiler flags and their idioms

Flags are in `build.sbt`, mirrored in `pants.toml`; main and test code compile under all of them. Keep the build
warning-free.

- **Capture checking, pure functions:** function types are `A -> B`; structures and test fixtures extend `caps.Pure`.
- **`strictEquality`:** `==` needs a `CanEqual`; laws compare with `=?=` or `===`. `Any.equals` is deprecated.
- **`-Yexplicit-nulls`:** Java APIs return `T | Null`; use `.nn`.
- **`-Wnonunit-statement`:** non-final asserts in tests are `val _ = assert(...)`.
- **Off on purpose:** `-Wsafe-init` (false positive when a *class* forwards a `tracked` parameter to a parameterized
  parent; don't add `@nowarn`, and prefer `lazy val` for members computed from parameters) and `-Wunused:imports`
  (false positive on renamed type imports such as `import target.--> as ==>`).

## The encoding of `parrot.category`

1. **Structures are `abstract class … extends caps.Pure`**. Type classes without parameters that are not structures
   (`Category.Type`, `Eq`, `Observable`, `Preorder`, `Measure`) are traits.
2. **What a structure is on is a `tracked val` parameter** (a stable path you can import from), named by its role in
   one lowercase word (`source`, `target`, `category`, `monoidal`, `strong`), indexed when there are two (`source1`,
   `source2`); what it adds is a member. A constraint between parameters refines the *later* one towards the earlier:
   `Classical(promonad: Promonad, cocartesian: Cocartesian { val category: promonad.category.type })`. A refinement
   forwards its parameter under the same name:
   `Promonad(tracked override val category: Category) extends Endoprofunctor(category, Total)`.
3. **`Self` iff the structure has its own carrier** (`Category`, `Functor`, `Promonad`, `Object`, `Monoid`, `Eq`, …),
   named by a `final` alias (`Hom`/`-->`, `F`, `P`, `A`, `M`, `C`). Structures *on* something (`Monoidal`, `Strong`,
   `Restriction`, `Monad`, the trace grid) have no `Self` and are named, not found by implicit search.
4. **Combinations are bundles, not inheritance** (`ParserAlgebra(…)` takes its structures as parameters); a structure
   that is another with more operations extends it (`Freyd`). A special case with an operation of its own is a class
   with a view to the general structure and a construction back (`Terminal.limit`, `Terminal.FromLimit`); aliases
   (`Monad.On`, `Limit.Of`) are only for pure refinements.
5. **Objects are types with evidence:** `type Obj <: Type` (`import Category.Type`; `Type.TIsType` holds for every
   type), passed only through context bounds, except an object a structure chooses or is on, which is a `tracked`
   parameter of type `category.Object`: a `Category.Object(category)` has the object as its carrier (`Self`, *A*) and
   its `evidence: A is category.Obj`. Such are the objects of `Product(category, factor1, factor2, apex)`, the apex of
   `Cone(diagram, apex)` and the unit of `Monoidal(category, unit, tensor)`, which `Cartesian` refines to a `Terminal`,
   an object with `discard`; instances of `Terminal(category)` and `Initial(category)` define `Self` and `evidence`.
   `category.Object[A]` builds one from a context bound, and `A is category.Object` is one of type *A*, so no structure
   takes bare evidence. Structures offer evidence only as values (`objects`, `evidence`, `apex`): every given is
   `private` to the class that uses it, refinements included (`private given IIsObj: (I is Obj) = unit.evidence`), and
   the only public givens are type class instances next to their type class.
6. **Instances are `object`s** nested in what they belong to (`Total.Products`, `Partial.Loops`); generic constructions
   are `open class`es (`Kleisli(monad)`, `StateT[S](monad)`). Instances name evidence explicitly (`Type.TIsType`), never
   `summon`: a class-level forwarding given would recurse.
7. **Operators are syntax:** each symbolic extension is `final`, passes its arguments in order to a named method
   (`f >>> g` is `andThen(f, g)`) and is documented `Infix extension for [[andThen]].`; an infix type alias is
   documented `Infix alias for [[Hom]].` One operator per operation: `>>>`/`<<<`, `***`, `&&&`/`|||`, `+++`, `**`,
   `|>`, `=?=`, `?<`, `===`.
8. **Arrows, not `.Self`:** write morphisms infix and bring them in with imports, never new type definitions
   (`import category.{Obj, -->, >>>}`, `import target.--> as ==>`). Roles: `-->` the category at hand, `->>` the second
   category of a pair (a bifunctor's or profunctor's second source, a strength's second category), `==>` a target
   category or a Freyd base, `~~>` an opposite. Concretely `A -> B` in `Total` (𝒮) and `A ~> B` in `Partial` (𝒫).
   Objects: `*`, `+`, `` `^` `` (`` B `^` A `` is *A* ⇒ *B*), `<->`.
9. **`final` on what is definitional:** aliases and members that only forward (`>>>`, `first`, `restricted`, the
   parser syntax); redefinitions are `override` without `final`. A member forwarded unchanged from a parameter is an
   `export` (no scaladoc); one that renames it or changes its meaning is a `final def` with its own doc
   (`ParserAlgebra.pure` is `parsers.unit(f)`). Eta-reduce aliases (`type Self = Tuple2`).
10. **Monads are structure on their functor** (`Monad(functor: Endofunctor)`, primitives `unit` and `flatten`). Refine
    through the functor, `Monad.On[Total.type]`, not `Monad { val category: Total.type }`, or the singleton chain
    breaks. Plain monads are transformers over `Monad.Identity`.
11. **Totality:** 𝒮 (`Total`) has total pure functions; 𝒫 (`Partial`, opaque `A ~> B`) may diverge and has the unguarded
    structures (restriction, loops, feedback, knots). Include a total `f` with `Partial.fromTotal(f)`, not `Partial(f)`;
    `Partial.assumeTotal` is the library's single totality promise. Total iteration and recursion are guarded by a
    `Measure` (`StateT.GuardedIteration`, `StateT.GuardedRecursion`).
12. **Laws:** every structure has `object <Name>Laws` returning `Boolean` and comparing with an `Observable` (`=?=`),
    never `Eq` on functions; inequations use a `Preorder` (`?<`). Congruence laws take variants equal by construction
    (`f2`); conditional laws state their premise in a `@note`.

One file per structure in `src/main/scala/parrot/category/`; the instances on 𝒮 and 𝒫 are in `Total.scala` and
`Partial.scala`; `Category.scala` also holds `Type`, `Object`, `Op`, the product category, `Empty` and `Discrete2`. A
family of structures shares its member's file: `Products` is in `Product.scala` and `Coproducts` in `Coproduct.scala`,
and the limits of a type of diagrams are in `Limit`'s companion (`Limit.OfDiagram`, `Limit.OfDiscreteDiagram`), the
colimits in `Colimit`'s.

## `parrot.parser`

- A parser `P[A, B]` consumes a prefix of the input while turning a semantic input `A` into a result `B`.
  `ParserAlgebra(parsers, products, coproducts, zipping, branching, choice, loops, knots)`: every combinator is an
  operation of one of these (`|>` is restriction override, i.e. PEG ordered choice). Loops and recursion are
  **guarded**: a step or call that makes no progress fails. Interpreters implement only `lift`, `literal`, `regex`,
  `rule` and `diagnose`.
- **Core invariant:** `StrictParser` behaves exactly like `ReferenceParser` (results, offsets **and diagnostics**) on
  every grammar without left recursion, which `StrictParser` additionally solves by seed growing. `AgreementTest`
  checks it on random `Grammars.terms`, the JSON tests on the corpora, and both interpreters run the same law specs.
- Diagnostics (`Expected`) are a join-semilattice written on success and failure; lookahead, negation, `failure` and
  guard failures are silent, which is why some `ParserLaws` are inequations.
- `StrictParser` run paths: no allocation beyond results, no boxing, `@tailrec` loops, no per-call closures. Functions
  passed to `Fn.lift` must be total and pure. `StrictParserTest` asserts the normal forms of the AST. Nodes must keep
  the invariant of `Info`, which drives choice dispatch: if a parser succeeds where the next character is `c`, then
  `c ∈ first`, or it is nullable and consumed nothing.

## Recipes

- **Structure:** derive behavior from existing structures where you can. A new structure goes into `category` with
  its laws, a spec and at least one instance; if `Foo` refines `Bar`, `FooSpec` extends `BarSpec`, and `Foo`'s
  instances lose their `Bar` test classes.
- **Combinator:** derive it in `ParserAlgebra` if possible, add a `Grammars.Term` case if it extends what grammars can
  express, add laws to `ParserLaws`, and test both interpreters.
- **Interpreter:** extend `ParserAlgebra(…)` with structures of the types its parameters require, implement the five
  primitives, and register it in `Interpreters` (in `Grammars.scala`), the law and structure specs, `AgreementTest` and
  `JsonGrammarTest`.
- **Grammar:** take a `ParserAlgebra` and `import algebra.*`; use `lift` for pure functions, `recursive` for
  self-reference (the call must follow consumed input), `recursive[(P[…], P[…])]` for mutual recursion and
  `p.rule(label)` for diagnostics. Running one: `val p = StrictParser(); val g = JsonGrammar(p);
  p.parse(g.json)(input)`.

## Code style

- Files start with two package clauses, `package parrot` then `package category`. scalafmt 3.11.3 (`.scalafmt.conf`,
  max 120 columns) has no CLI here: touch only the lines you change; files with given syntax scalafmt cannot parse are
  formatted by hand.
- Method bodies and `match`es in braces; `if … then … else`; aligned `=`, `:` and `=>` in consecutive declarations
  and cases; trailing commas in multi-line lists; braces in imports only around several selectors
  (`import category.-->`, `import category.{Obj, -->}`).
- No unicode in code, and diagrammatic composition (`>>>`) there; unicode math and `∘` only in scaladoc.
- **Every** public member has scaladoc, exports excepted. Math: variables in `*italics*`, categories in `**bold**` or
  as 𝒮 and 𝒫, `∘` for composition, no spaces in argument lists (`**C**(*A*,*B*)`). Laws state their equation first.
  Structure docs begin "A … on …", then "Represents …, where" and bullets. Caveats go in `@note`.
- Names: givens `<Carrier>Is<TypeClass>`, laws objects `<Structure>Laws`, `@targetName`s `<method>Ext`, structure
  parameters lowercase role names (rule 2), while scaladoc keeps the mathematical letters (**C**, *F*). Morphisms run
  from `A` to `B`, indexed per component (`bimap(f: A1 --> B1, g: A2 ->> B2)`).
- Code in `category` is pure, immutable and total; mutation only in `StrictParser` state, `Scanner`, tests and
  benchmarks.

## Tests

- `LawSuite(structure, instance)` with `law(name) { … }`, `counterexample(name) { … }` and `forAll(…)`; it provides the
  instance under test as a given, and laws of another structure the instance has go in `also("Name") { … }`. Test
  names: `"<Instance> is <Structure>: <law>"`.
- **One generic spec per laws object**, in the test file named after the laws' source file (`ElgotSpec` in
  `ElgotTest.scala`), and **one test class per instance**, at its most specific structure. A refinement's spec extends
  its parent's, forwarding the subject under the same name; coverage is transitive (`Total.Products` has only a
  Cartesian test class). An extensible spec takes `structure: String = "<Name>"` last, passes it to `LawSuite` and
  registers its laws in `also("<Name>")`, so a child reports them under its own name. Where the parent's spec needs
  other fixtures, the child copies its laws into an `also` block instead (`FreydSpec`, `PromonadSpec`). `IsoLaws` has
  no spec: `MonoidalLaws` and `ModuleLaws` check it.
- **Specs take their subject, not a fixture:** `tracked val monoidal: Symmetric { … }`, named after its structure, with
  the fixture found as a given, `using category: CategoryFixture.On[monoidal.category.type]`; where the subject takes
  the fixture's name (`CategorySpec`, `BifunctorSpec`, `PromonadSpec`), the fixture is `fixture`. There is one given
  fixture per category or promonad, in the `CategoryFixture` and `PromonadFixture` companions (the parser's in
  `ParserFixtures`, in `Grammars.scala`); derived categories (`Total.op`) need their own. `FunctorSpec` takes two,
  `source` and `target`. A spec whose instance is named after a type takes `typename: TypeName[T]`
  (`class IntIsEqTest extends EqSpec[Int]`).
- **Fixtures:** `Sample[X]` is a generator, a cogenerator and an `Eq` (a carrier without `Eq` is sampled where it is
  data: `StateT` at `Boolean` states); `CategoryFixture` has `arrow`, `variant` and `observe`; `PromonadFixture` adds
  `category`, the fixture of the promonad's category, for pure arrows, and `arrows`, the fixture of its category of
  arrows. Helpers several test files share go in a fixture file without `Test` (`GridFixture.scala`).
- **Sample types:** specs are generic in `T1`–`T4` of `using types: SampleTypes` (`import types.{T1, T2, given}`;
  default `SampleTypes.Standard`: `Int`, `String`, `Boolean`, `Long`). Using clauses list the fixture, then `types`,
  then samples, which come from polymorphic givens (`Sample.Tuple2Samples`) where the test class is declared, so test
  classes need no sampling code. Types a generator forces stay concrete (the `Int` states of loops).
- Law bodies import the fixture (`import category.*`), the carrier and the laws (an `also` structure's inside its
  block), bind generators to vals named after what they sample (`val fs = arrow[T1, T2]`), then, after a blank line,
  `forAll(observations, fs) { (observe, f) => … }`.
- Conditional laws use targeted generators (`Descent`, `StringStateFixture.guarded`, `refined` pairs for
  monotonicity), not `==>`. Counterexample tests document intended semantics: keep them.

## Lessons: check here before fighting the compiler

- **Spike first.** For "does the type system accept X", compile a twenty-line file with Scala CLI at the library's
  version and flags: `scala compile --server=false -S 3.10.0 -O <flag> …`, one `-O` per flag in `build.sbt`.
- **Singleton chains.** Path-dependent code type-checks only if every link is a singleton type (`promonad.category` =
  `monad.functor.category` = `Total`); refine the parameter a member comes from (`Monad.On`), never intersect.
- **A refinement sees the members of the type it refines,** so a name that is also one of them is cyclic or ambiguous
  inside it: `Product { val category: category.type }`, or `Limit.Of[diagram.type] { val apex: diagram.… }` for a
  parameter `diagram`. Refine through an alias declared elsewhere (`Product.Of[category.type]`), import what the
  refinement names (`import category.Object`), use a `this`-qualified path in methods
  (`OpCoproducts.this.cartesian.type`), or give a method parameter another name (`limit(functor)`).
- **Anonymous subclasses lose the parent's tracked refinement**: use a named class (`Bistrong.Op`).
- **A parent's arguments cannot name the class's members**, since `this` does not exist yet: a type that an instance
  passes to its parent (the points of `Total.LimitOf`) goes into the companion, indexed by the parameter it depends on
  (`LimitOf.Point.Of[diagram.type]`). Nor can its type arguments name the class's parameters: an instance whose type of
  diagrams depends on a parameter is a method returning an anonymous instance (`Total.DiscreteLimitsOf(index)`).
- **`export functor.category`** creates a stable alias: imports from it and singleton chains keep working.
- **Same-named extensions from two imports overload** by the receiver's type, and extensions are also found through a
  path-dependent type's prefix (`category.Hom` finds `category.>>>` without an import). Where one value is an arrow of
  two structures (a Kleisli arrow on 𝒮, a promonad and its `arrows`), both `>>>` apply: import one and name the other
  (`monad.category.andThen(…)`). The failure is always a compile error, never a wrong composition.
- **Infix precedence** goes by first character: `*` > `+`, `-->`, `->>` > `<->` > `==>` > `^` > `is`, with `~>` and
  `~~>` tightest. Parenthesize mixed arrows and tensors (`(A + B) --> C`, `(A ~> B) is Observable`). `?<` binds tighter
  than every other term operator; `<?` would start an XML literal.
- **Givens.** No given with `Self = Nothing`: it matches every `T is TC` (`Eq.NothingIsEq` is a `val`). A generic and a
  specific given in one object are ambiguous: put the fallback in a parent trait of the companion
  (`object Observable extends ComponentwiseObservable`). `CanEqual` is not an equality: build `Eq` with `Eq.structural`.
  Exporting a given whose type depends on a path fails under capture checking (`docs/compiler-issues.md`): name the
  type and declare a private given instead (`Monoidal.I = unit.A` and `IIsObj`).
- **Nullary extensions** that clash with a method of the same name take `(using DummyImplicit)`.
- **Imports.** `import monoidal.{*, ***}` is an error, since `*` is the wildcard; import a tensor alias `*` backticked:
  ``import monoidal.{I, `*`, given}``. Pants infers no dependency from a relative import at the top of a file
  (`import Category.Discrete2.Disc2` after the package clauses), and `pants check` can then fail with "Not found": put
  the import inside the definition that uses it (`object Sample`).
- **GADTs and evidence.** Matching refines type parameters, not type members, so a match on `A is Disc2` never refines
  `A`: carry a GADT on the evidence and match on it (`A.index match { case Index.Zero => … }`). A match type at the
  refined parameter still does not reduce where a value must conform to its case (`x: Components[X, Y][A]` is not an
  `X` in the case `Zero`): convert with the case's equality,
  `summon[A =:= 0].substituteCo[[T] =>> Components[X, Y][T]](x)`.
- **Capture checking.** Patterns of case classes without fields (`Proj1()`) crash it: write `case _: Proj1[?, ?]`. A
  given declared with an unreduced match type (`given (category.-->[(Int, Long), …] is Observable)`) fails: declare it
  in reduced form. A polymorphic function type cannot wrap an impure one: `[X] => Sample[X] ?-> Sample[F[X]]`.
- **Capture checking in tests.** Lambdas inside ScalaTest's `assert` macro can fail ("Illegal capture reference"):
  compute the value outside. Annotate ScalaCheck lambda parameters with pure types. Helpers called from generator
  lambdas go in an object, not the test class (`Descent`).
- **Inline methods.** A given defined in the algebra is not found through an inline proxy path, and abstract type
  constructors cannot take wildcards: pass evidence as a `using` parameter resolved at the call site
  (`ParserAlgebra.Parsers`). In a public inline method, compare private singletons with `eq`.

## Git

`main`, linear history (rebase), one logical change per commit. Subjects are lowercase, past tense, without a period,
starting with a verb (`added XTest`, `renamed …`, `fixed …`); the body is a paragraph on what changed and which docs
were updated; no `Co-Authored-By` trailer. Never commit `target/`, `.bsp/` or `.idea`.
